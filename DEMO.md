# Demo script (CS698B / FDE1 project, 29 Nov 2026)

Two teams, two stories:

| Team | Data | What it shows |
|---|---|---|
| **Demo Studio (synthetic)** | generated by `scripts/make_demo_team.py`: 90 posts, 60 other-club posts, 40 briefs x 3 versions decided by simulated seniors | the whole learning loop, including the approval model, which needs many decided designs |
| **Techkriti** (real, local only) | 74 Instagram posts, 9 rejected + 2 accepted designs | what works on real data today and what doesn't (KNOWN_ISSUES.md) |

Say it plainly: Demo Studio is invented, with consistent rules we wrote; it proves the machinery learns.
Techkriti is real; there the on-brand score works and the approval model is (correctly) still off.

## Setup (once)

```bash
.venv/Scripts/python scripts/make_demo_team.py          # ~5-8 min: generates, imports, trains into data_demo/
.venv/Scripts/python scripts/eval_demo_team.py          # held-out numbers for the slides
```
Start the demo server (VIBE_DATA_DIR=data_demo, port 8001; `vibecheck-demo` in launch.json) and the contrast plugin
on 8100 if you want to show cross-dev plugins. The live-demo posters are in `data_demo/generated/demo_kit/`
(`ANSWERS.json` has what the simulated seniors decided).

## Flow (about 8 minutes)

1. **Problem** (30 s): new designer, unknown team taste, wasted work.
2. **ETL** (1 min): Team setup → counts; posting history with dates and likes; other clubs; decided designs with
   projects. Mention Instagram import with `since`, daily refresh, re-embedding when the model changes.
3. **Team style** (1.5 min): style map, signature palette, usual ranges, trend, what gets likes.
   Model health tiles: approval model **On** with its leave-one-brief-out AUC; new-post calibration.
4. **Check my idea** (1 min): upload 1-2 inspiration images + description → score, reasons, closest posts.
5. **Check my design** (2 min): upload a kit poster that the seniors rejected (e.g. off palette or tiny title) →
   Off-brand/Borderline, reasons, finish checklist, learned approval %. Then the accepted version of the same brief
   → higher. Link it to the plan check to show "plan vs final".
6. **Adaptive loop** (1 min): mark the outcome in History → it becomes a decided design → Retrain → the approval
   model's counts go up (Team style tiles).
7. **Developer API + plugin** (1 min): /docs (OpenAPI 3), docs/api.html, the contrast-checker plugin panel on Result.
8. **Honesty slide** (30 s): Techkriti numbers (KNOWN_ISSUES), what synthetic data can and can't show, ~30-50
   decided briefs needed for a real team (scripts/simulate_seniors.py).

## Numbers for the slides (12 Nov 2026 build)

**Demo Studio (synthetic)**, 90 posts + 60 other-club posts + 40 decided briefs (55 accepted / 65 rejected versions):
- Approval model switched itself on: leave-one-brief-out AUC 0.81 (90 % interval low end 0.76), weight 60 %.
- On 60 NEW briefs it never saw (180 versions), accepted vs rejected:

| | AUC | Top-scored version was the seniors' pick |
|---|---|---|
| on-brand score alone (no decisions needed) | 0.61 | 55 % |
| **final score, learned from decisions** | **0.74** | **68 %** |
| ceiling: the simulated seniors' own hidden score (10 % of decisions flipped) | 0.92 | - |

- Learned well: off palette (median score 24), tiny title (25), low contrast (27), busy background (35).
  Missed: wrong font (63) and small clutter (51), because no feature describes type or small stickers yet.
- Demo kit: within each brief the accepted version scores highest (Neural Nights 73 > 65 > 18; Build Week 93 > 67),
  but a wrong-font version can still read "On-brand": good honest talking point.

**Techkriti (real)**: on-brand v6, time-forward AUC 0.90 on 33 unseen real posts; both accepted designs above all 9
rejected drafts; approval model off (2 accepted, 1 more brief needed, and ~30-50 briefs before it would help).
