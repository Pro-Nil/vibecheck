VibeCheck API v1.0.0 · OpenAPI 3.1.0

VibeCheck learns a design team's visual style from its Instagram feed and scores a designer's plan (inspiration images + a short description) before they design: a 0–100 vibe-match score, the reasons, and the team's closest past posts.

Plain JSON over HTTP. No authentication yet. Images are uploaded as multipart/form-data. In the examples, $API is the server address, e.g. http://localhost:8000 (run it from github.com/Pro-Nil/vibecheck). A live, clickable version of these docs is at $API/docs; the raw spec is at $API/openapi.json.

Score a planPOST /teams/{id}/checks
Team's learned styleGET /teams/{id}/style-profile
Add a pluginPOST /plugins
Features of any imagePOST /features

Long jobs (import, retrain) return a job_id at once; poll GET /jobs/{id} until status is done or failed. Scores are 0–100; style features are 0–1. Errors return {"detail": "…"} with a 4xx code (409 = team has no trained model yet).

Build a plugin (cross-dev)

A plugin is your own small web service with one POST endpoint. It runs inside our app: we send it the data, it returns a Panel, and we draw that panel with our own components on the Result page (or the Team style page). You do not build a separate app.

  1. Write the service. Any language; it must answer within 5 seconds with Panel JSON.
  2. Register it once: POST /plugins with its URL and where it shows ("slot": "result" or "profile"). Or use the Plugins page in the app.
  3. Done. Every new check calls your URL. Errors and timeouts show as a small note, never break the page.

Minimal plugin (Python)

# my_plugin.py  ->  run:  uvicorn my_plugin:app --port 8100
from fastapi import FastAPI

app = FastAPI()

@app.post("/hook")
def hook(event: dict):
    check = event.get("check", {})          # for event == "check.completed"
    palette = check.get("plan_palette", [])
    # ... your own data + model here ...
    return {
        "title": "My plugin",
        "summary": "One line about what this panel shows.",
        "metrics": [{"label": "Colours used", "value": len(palette)}],
        "items": [{"ok": True, "text": "Something that fits."},
                  {"ok": False, "text": "Something to fix."}],
        "chart": {"type": "bar", "title": "Share of each colour", "y_label": "%",
                  "points": [{"label": c["hex"], "value": round(100 * c["share"])}
                             for c in palette if isinstance(c, dict)]},
    }

Full working example: plugins/contrast_checker/app.py in the repo (github.com/Pro-Nil/vibecheck).

Course rule: a cross-dev plugin needs its own data, adaptive and visualization parts. Data: what we send plus anything you fetch. Adaptive: your model or rules. Visualization: the Panel's chart, metrics and items.

Checks

Score a designer's plan (the main call).

POST /teams/{team_id}/checks

Score a plan (1-5 inspiration images and/or a description) or a finished design (kind=final, 1 image)

Parameters

NameInTypeDescription
team_id requiredpathinteger

Form fields (multipart/form-data)

FieldTypeDescription
imagesarray of file1-5 inspiration images (JPG, PNG or WebP, up to 15 MB each). Repeat the field once per image.
descriptionstringWhat you plan to make: colours, layout, fonts, photo or illustration. Send images, a description, or both.
userstringWho is checking (optional, shown in History).
kindstringplan = inspiration before designing; final = your finished design (exactly 1 image): adds finish checks (legibility, text size, edges, resolution) and the learned approval model. Default: "plan".
plan_check_idinteger | nullFor kind=final: the plan check this design came from, to compare the final with its plan.
projectstringWhich brief/project this is for (optional). Lets decisions on versions of one brief train the approval model.

Example request

curl -X POST $API/teams/1/checks \
  -F "images=@inspo1.jpg" -F "images=@inspo2.png" \
  -F "description=dark background, neon green code text, big bold title" -F "user=asha"
